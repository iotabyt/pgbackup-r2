`pgb` is a short script around `docker run`. Docker is the only thing it needs: no Python, `pg_dump` or `age` on your machine.

## Install

<Tabs syncKey="shell">
<TabItem label="bash">

```bash
curl -fsSL https://pgbackup-r2.iotabyt.com/install.sh | sh
```

</TabItem>
<TabItem label="zsh">

```zsh
curl -fsSL https://pgbackup-r2.iotabyt.com/install.sh | sh
```

zsh is the default shell on macOS.

</TabItem>
<TabItem label="fish">

```fish
curl -fsSL https://pgbackup-r2.iotabyt.com/install.sh | sh
```

</TabItem>
<TabItem label="PowerShell">

```powershell
irm https://pgbackup-r2.iotabyt.com/install.ps1 | iex
```

This installs the latest release. It saves `pgb.ps1` in `~\.pgb`, and adds a `pgb` function to your `$PROFILE` between two marker comments, which is how `pgb uninstall` later finds it. Running it again updates `pgb.ps1` and leaves `$PROFILE` alone. It works in Windows PowerShell 5.1 and PowerShell 7, on any OS.

If PowerShell refuses to run scripts:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

</TabItem>
</Tabs>

The bash, zsh and fish installer puts the latest release of `pgb` in `~/.local/bin`. **`pgb` itself always runs with bash,** so it behaves the same whichever shell you type it in.

Check it:

```bash
pgb version
```

## Install a specific version

The install lines fetch `pgb` from the latest release on GitHub, never from the `main` branch, which can be mid-change. To install a particular release, name it with `PGB_VERSION`:

<Tabs syncKey="shell">
<TabItem label="bash, zsh, fish">

```bash
curl -fsSL https://pgbackup-r2.iotabyt.com/install.sh | PGB_VERSION=v0.4.3 sh
```

</TabItem>
<TabItem label="PowerShell">

```powershell
$env:PGB_VERSION = 'v0.4.3'; irm https://pgbackup-r2.iotabyt.com/install.ps1 | iex
```

</TabItem>
</Tabs>

The releases are listed at [github.com/iotabyt/pgbackup-r2/tags](https://github.com/iotabyt/pgbackup-r2/tags).

To find the latest release, the installer asks GitHub's API. It allows 60 requests an hour from one address. If the API can't be reached, the installer stops with a message rather than installing from `main`. Naming a version with `PGB_VERSION` skips the API altogether.

## Install without the short URL

The install lines above download from `pgbackup-r2.iotabyt.com`, which redirects to the scripts on GitHub. Some company proxies block redirects. If yours does, download straight from GitHub instead:

<Tabs syncKey="shell">
<TabItem label="bash, zsh, fish">

```bash
curl -fsSL https://raw.githubusercontent.com/iotabyt/pgbackup-r2/main/scripts/install.sh | sh
```

</TabItem>
<TabItem label="PowerShell">

```powershell
irm https://raw.githubusercontent.com/iotabyt/pgbackup-r2/main/scripts/install.ps1 | iex
```

</TabItem>
</Tabs>

## Put `~/.local/bin` on your PATH

The installer checks your `PATH`. If `~/.local/bin` isn't on it, the installer prints the line for your shell (from `$SHELL`). It never edits your shell's files itself. Run the line once:

<Tabs syncKey="shell">
<TabItem label="bash">

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
```

On macOS, terminals start login shells, which read `~/.bash_profile` instead. Use that file in place of `~/.bashrc`.

</TabItem>
<TabItem label="zsh">

```zsh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

</TabItem>
<TabItem label="fish">

```fish
fish_add_path ~/.local/bin
```

</TabItem>
<TabItem label="PowerShell">

Nothing to do: `pgb` is a function in your `$PROFILE`, not a file on `PATH`.

</TabItem>
</Tabs>

## macOS and bash 3.2

macOS ships bash 3.2 from 2007, and `pgb` works with it. It avoids everything newer: associative arrays, `mapfile`, `${var,,}` and `|&`. CI runs `pgb` under bash 3.2 to keep it that way.

## Update

- **`pgb` itself:** run the install line again. It installs the latest release.
- **The image:** run `pgb update`. It pulls the image for your `PG_MAJOR`, prints the old and new versions, and tells you if `pgb nightly` needs a restart to use it.

## Uninstalling

```bash
pgb uninstall          # pgb itself
pgb uninstall --all    # also the pgb nightly containers and the pgbackup-r2 images
```

It lists exactly what it will remove and asks before removing anything. `--yes` skips the question. Run without a terminal and without `--yes`, it refuses.

- **`pgb uninstall`** removes the `pgb` script. In PowerShell, it also removes `~\.pgb` and the `pgb` function from `$PROFILE`: only the lines between the installer's marker comments (or the single `function pgb` line that older installs added), never anything else in the file.
- **`--all`** also stops and removes the `pgb nightly` containers, and removes the `ghcr.io/iotabyt/pgbackup-r2` images. It only touches containers and images carrying pgbackup-r2's own image label, so other containers are never at risk.
- **Without `--all`, a running `pgb nightly` container keeps running,** and keeps taking backups. `pgb uninstall` warns you. Run `pgb nightly stop` in its folder first if you want the backups to stop.

**Never touched, either way:**

- your backups in the bucket, with their manifests and `.drills/` records
- your `.env` files and `out/` folders
- your keys

Your private key is still wherever you saved it, and you need it to open your old backups.

Running it twice is safe. The second time, it says `pgb is not installed` and stops.

### If you already deleted the script

<Tabs syncKey="shell">
<TabItem label="bash, zsh, fish">

```bash
rm -f ~/.local/bin/pgb
# The pgb nightly containers, found by pgbackup-r2's image label:
docker ps -a --filter "label=org.opencontainers.image.source=https://github.com/iotabyt/pgbackup-r2" --filter name=pgbackup
docker rm -f pgbackup-shop                             # each name listed above
docker image rm ghcr.io/iotabyt/pgbackup-r2:pg16       # and :pg17, :pg18, :pg19 if you pulled them
```

</TabItem>
<TabItem label="PowerShell">

```powershell
Remove-Item -Recurse -Force (Join-Path $HOME .pgb)
notepad $PROFILE    # delete the lines from "# >>> pgb" to "# <<< pgb <<<"
docker ps -a --filter "label=org.opencontainers.image.source=https://github.com/iotabyt/pgbackup-r2" --filter name=pgbackup
docker rm -f pgbackup-shop                             # each name listed above
docker image rm ghcr.io/iotabyt/pgbackup-r2:pg16
```

Older installs added a single `function pgb { ... }` line instead of the marked block. Delete that line.

</TabItem>
</Tabs>

## Without Docker

If you'd rather not use Docker, install the Python package from PyPI:

```bash
pip install pgbackup-r2
# or, with uv:
uv tool install pgbackup-r2
```

To try it without installing anything, `uvx pgbackup-r2 --version` runs it straight from PyPI.

It needs `pg_dump`, `pg_restore` and `psql` from the same Postgres major version as your server, plus `age` (`apt install age`, `brew install age`), all on `PATH`.

**pgbackup-r2 doesn't read `.env` itself.** Settings come from [environment variables](/reference/environment/) only: `pgb` hands `.env` to Docker, and without `pgb`, nothing does. Keep them in a `.env` that only you can read, and load it into your shell before running anything:

```bash
set -a; source .env; set +a
pgbackup-r2 doctor
```

`set -a` exports every variable the file sets, so `pgbackup-r2` sees them. Quote values with spaces, as in `TIERS="daily=daily/ monthly=monthly/"`: the shell reads the file, so an unquoted space ends the value. If a `.env` sits in the current folder but isn't loaded, `pgbackup-r2 doctor` says so.

Run `pgbackup-r2 backup` (and the other [CLI commands](/reference/cli/)) from plain cron:

```text
# /etc/cron.d/pgbackup-r2
0 2 * * *  backup  . /etc/pgbackup-r2.env && pgbackup-r2 backup
```

Use `export VAR=value` lines in the env file when you source it like this. Outside a terminal, output is plain log lines, so cron mail and log files stay readable.

<Aside>
`pgb` only exists for the Docker route. Without Docker, the commands are `pgbackup-r2 backup`, `pgbackup-r2 drill` and so on, and you provide the drill's scratch database (`DRILL_DATABASE_URL`) yourself.
</Aside>
